AI-Powered Personal Expense Intelligence System
A Python and Streamlit application that analyses bank-transaction CSV files, summarizes income and expenses, categorizes transaction descriptions, highlights potentially unusual expenses, and provides basic spending insights.
Project status: Academic prototype. It analyses files supplied by the user; it does not connect directly to a bank account or initiate transactions.

Features
- CSV upload and validation: Upload a bank transaction CSV and check required fields before analysis.
- Transaction normalization: Standardizes supported bank-export column names and handles debit/credit columns where supported by the data loader.
- Hybrid transaction categorization: Checks known description keywords first, then uses the trained text-classification model for descriptions that do not match a rule. Existing assigned categories are retained during automatic processing.
- Financial overview: Displays total income, total expenses, net cash flow, and transaction count.
- Spending charts: Shows month-wise spending and spending distribution by category.
- Top expenses: Lists the five largest expense transactions.
- Spending insights: Produces rule-based suggestions from transaction totals and categories. These are not generated by a large language model.
- Transaction explorer: Search by description, filter by category or transaction type, and download the visible filtered rows as CSV.
- Unusual expense detection: Uses Isolation Forest to flag potentially unusual expense amounts for review.
- Category Predictor: Allows a user to enter one description and see a predicted category.
- Model evaluation: Compares the text classifier by itself with the keyword-plus-model hybrid system, and saves classification reports and confusion matrices.

Setup on Windows
Open the VS Code terminal in the project root—the folder containing app.py—and run:
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
If PowerShell blocks virtual-environment activation, follow your local machine's PowerShell policy guidance, or use the VS Code terminal profile you normally use for Python.

If the project does not yet have a requirements.txt, install the dependencies used by the application:
python -m pip install streamlit pandas plotly joblib scikit-learn matplotlib pytest
Run the dashboard
From the project root, with the virtual environment activated:
streamlit run app.py
The app uses the sample CSV when no upload is supplied. To analyse your own data, use the CSV upload control in the sidebar. The dashboard analyses the records loaded from that file; it does not fetch new transactions from a bank automatically.
CSV format
The standardized transaction table uses these columns:
Date,Description,Category,Method,Amount
2026-10-07,Medicine Purchase,Unclassified,UPI,-500
2026-10-08,Salary Credit,Income,Bank Transfer,50000
Column guidance
Column	Purpose
Date	Transaction date
Description	Bank narration or transaction description
Category	Existing category, or Unclassified when it needs categorization
Method	Payment method, such as UPI, card, or bank transfer
Amount	Numeric amount; in the current project convention, expenses are negative and income/credits are positive


The loader requires the transaction date, description, and amount. Category and method may be defaulted by the loader when absent. Supported bank-export aliases and separate debit/credit columns depend on the mappings implemented in src/data_loader.py. Always verify a few rows against the original bank statement before relying on the analysis.
Train the category model
Training examples are stored in data/training_transactions.csv. The file needs at least Description and Category columns.
python train_models.py
The command trains the text classifier and saves it as:
models/category_model.joblib
Note: Training again can overwrite the saved model. Make a copy of the existing model first if you need to preserve it.
Evaluate categorization
The evaluation script compares:
1. ML-only: TF-IDF text features with a Logistic Regression classifier.
2. Hybrid: the keyword rules in src/categorization.py, with the trained classifier as a fallback.
The evaluation script uses two separate files:
- Training file: data/training_transactions.csv
- Unseen test file: data/unseen_test_transactions.csv
Run:
python evaluate_model.py
Reports are written to reports/, including accuracy/precision/recall/F1-score tables, individual predictions, incorrect predictions, and confusion-matrix images. Keep the unseen test descriptions out of the training data and do not add them to keyword rules before evaluating them. Once test examples are used to tune rules, they are no longer an independent test set; create a new unseen set for a fair evaluation.
Run tests
pytest -q
Run the tests after changes to data loading, categorization, analysis, recommendations, or anomaly detection.
How categorization works
1. A CSV is loaded and normalized.
2. Rows with an already assigned category generally retain that category.
3. For rows marked Unclassified, blank, or Unknown, the app calls predict_category().
4. The prediction function checks the keyword rules first.
5. If no rule matches, it asks the trained ML classifier for a prediction.
Because keyword rules have priority, the hybrid system's score can differ from the ML-only score. A correct result for a keyword-covered description does not necessarily mean the ML classifier itself learned that pattern.
How anomaly detection works
src/anomaly_detection.py uses IsolationForest on the positive magnitude of negative expense amounts. The current implementation requires at least five expense transactions. It flags amounts that look unusual relative to the selected data; it does not confirm fraud, theft, or an unauthorized transaction. A flagged item should be reviewed against the original statement and the user's own context.
Limitations and responsible use
- The training and unseen evaluation examples currently used in development are synthetic. Their results may not represent performance on real bank statements.
- The current unseen evaluation set is small. Accuracy and per-category metrics can change substantially with a different split or new descriptions.
- Keyword rules work well for known phrases but may miss new merchant names, abbreviations, typos, multilingual descriptions, or ambiguous narrations.
- The model predicts from transaction text; its quality depends on the coverage and correctness of labelled training examples.
- Anomaly detection uses the transaction amount only in the current implementation; an unusual amount is not automatically suspicious or fraudulent.
- Review the uploaded data, predictions, and exported CSV before making financial decisions. Do not treat the prototype as professional financial advice or a fraud-detection guarantee.
- The project processes a user-provided CSV and does not directly access bank credentials or accounts.
Suggested future improvements
- Expand and validate the training data with appropriately anonymized real-world-style descriptions.
- Create a larger, untouched holdout test dataset and evaluate the full categorization workflow.
- Add confidence/uncertainty handling for ambiguous predictions and allow users to correct categories.
- Improve anomaly detection with additional features and user-reviewed examples.
- Add exportable summary reports and a clearer model evaluation page in the dashboard.
- Add more robust tests for bank CSV formats, missing data, income transactions, and empty/short datasets.
Academic project note
This project demonstrates data loading and cleaning, text classification, rule-based processing, exploratory financial analysis, anomaly detection, and a Streamlit user interface. Any reported model metrics should always be presented with their dataset size and limitations.
